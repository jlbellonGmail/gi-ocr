# Spec T3.5 — CLI Document Processing with JSON Export

## Objetivo
Convertir el flujo T3.4 existente en una herramienta CLI estable para usuario, capaz de recibir una imagen/documento, ejecutar el pipeline OCR, mostrar resumen de campos y guardar resultado JSON completo.

## Problema de usuario
El usuario necesita procesar documentos individuales desde línea de comandos, obtener salida estructurada en JSON y recibir feedback claro del procesamiento (campos aceptados, rechazados, no encontrados).

## Estado base
- T3.4 formalmente cerrado (commit `8e442b7`, merge `1f8388a`)
- Pipeline OCR funcional en `scripts/t3_4_visible_flow.py`
- Componentes reutilizables: `backend/app/t3_2_orchestrator.py`, `backend/app/field_reporting_processor.py`, `backend/app/gas_extractor.py`
- Fixture de prueba: `backend/tests/fixtures/gas_sample.jpg`
- Tests de regresión: `backend/tests/test_t3_4_visible_flow.py`

## Alcance
- Script CLI `scripts/process_document.py` con `argparse`
- Argumentos obligatorios: `--input` (archivo), `--output` (JSON)
- Reutilizar pipeline T3.4 sin duplicar lógica
- Capa de exportación JSON separada (`backend/app/document_result_exporter.py`)
- Resumen legible en stdout: accepted/rejected/missing counts + cliente/importe
- Códigos de salida deterministas (0=éxito, 1=error entrada, 2=error exportación, 3=error pipeline)
- Manejo de errores operativos sin traceback
- Tests: caso exitoso, entrada inválida, error exportación, regresión T3.4

## Fuera de alcance
- Interfaz web / API
- Corrección humana (HITL) interactiva
- Almacenamiento histórico / base de datos
- Segundo tipo documental
- Métricas agregadas / dashboards

- Hardcodear reglas GAS en CLI

## Contrato CLI
```bash
python scripts/process_document.py --input <ruta_documento> --output <ruta_resultado.json>
```

### Códigos de salida
| Código | Significado |
|--------|-------------|
| 0 | Éxito completo |
| 1 | Archivo de entrada no existe / no legible |
| 2 | Error escribiendo archivo de salida |
| 3 | Fallo en pipeline OCR/extracción/validación |

### Salida stdout (resumen)
```
Procesamiento completado: documento.jpg → resultado.json
Campos aceptados: 3 | Rechazados: 0 | No encontrados: 2
Cliente: 12345678 | Importe: 123.45 (aceptado)
```

## Contrato de salida JSON
Estructura completa preservada de T3.4:
```json
{
  "raw_ocr_text": "...",
  "structured_output": {
    "document_type": "invoice",
    "source_document_reference": "...",
    "candidate_fields": {...},
    "validated_fields": {...},
    "rejected_fields": {...},
    "missing_fields": {...}
  },
  "field_report": {
    "summary_counts": {"accepted_count": 3, "rejected_count": 0, "missing_count": 2},
    "accepted_fields": [...],
    "rejected_fields": [...],
    "missing_fields": [...]
  },
  "processing_metadata": {...}
}
```

## Manejo de errores
- Entrada inexistente: mensaje claro "ERROR: Archivo no encontrado: <path>", exit 1
- Ruta salida no escribible: mensaje claro "ERROR: No se puede escribir: <path>", exit 2
- Fallo pipeline: mensaje "ERROR: Fallo en procesamiento: <detalle>", exit 3
- Nunca imprimir traceback para errores operativos esperables
